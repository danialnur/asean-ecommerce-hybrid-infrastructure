Wazuh manager syslog listener - live verification transcript
================================================================
Captured 2026-08-03. Standalone `docker run` tests against
wazuh/wazuh-manager:4.9.0 directly (no full stack, no certs needed) -
see logging-dashboard/README.md's "Live Deployment Attempt" item 4 for
the full narrative. Raw commands and real output, not paraphrased.

------------------------------------------------------------------
1. CONFIRMED: the image's own default ossec.conf has NO syslog listener
------------------------------------------------------------------
$ docker run --rm --entrypoint cat wazuh/wazuh-manager:4.9.0 \
    /var/ossec/data_tmp/permanent/var/ossec/etc/ossec.conf
  ...
  <remote>
    <connection>secure</connection>
    <port>1514</port>
    <protocol>tcp</protocol>
    <queue_size>131072</queue_size>
  </remote>
  ...
-> Only one <remote> block, connection=secure (encrypted agent
   enrollment), 1514/tcp. No syslog listener anywhere in the default.

------------------------------------------------------------------
2. Single-file bind mount fails - Wazuh's own init script edits the
   file in place, which a bind-mounted single file can't survive
------------------------------------------------------------------
$ docker run --rm -d -v ".../config/ossec.conf:/var/ossec/etc/ossec.conf" \
    wazuh/wazuh-manager:4.9.0
...
sed: cannot rename /var/ossec/etc/sed8mn2oB: Device or resource busy
...
wazuh-analysisd: CRITICAL: (1202): Configuration error at 'etc/ossec.conf'.
wazuh-analysisd: Configuration error. Exiting
-> Same failure whether the mount was :ro or writable - a general
   Docker single-file-bind-mount limitation (rename-based in-place
   edits can't target a bind-mounted inode), not a permissions issue.

------------------------------------------------------------------
3. Fix: found and used Wazuh's own documented mount point
------------------------------------------------------------------
Read /etc/cont-init.d/0-wazuh-init directly inside the image:
  WAZUH_CONFIG_MOUNT=/wazuh-config-mount
  mount_files() {
    if [ -e "$WAZUH_CONFIG_MOUNT" ]; then
      cp --verbose -r $WAZUH_CONFIG_MOUNT/* $WAZUH_INSTALL_PATH
    fi
  }
-> Mount custom files into /wazuh-config-mount/etc/... instead; the
   container COPIES them into place (not a bind-mount replace), so the
   result is a normal writable file the init script's sed edits work on.

$ docker run --rm -d \
    -v ".../config/ossec.conf:/wazuh-config-mount/etc/ossec.conf:ro" \
    wazuh/wazuh-manager:4.9.0
-> No config errors. wazuh-remoted starts successfully.

------------------------------------------------------------------
4. Confirmed the syslog listener is genuinely up (with our fix's
   <remote connection="syslog"> block added)
------------------------------------------------------------------
$ docker exec <container> grep -i remoted /var/ossec/logs/ossec.log

wazuh-remoted: INFO: Started (pid: 601). Listening on port 1514/TCP (secure).
wazuh-remoted: INFO: Started (pid: 602). Listening on port 514/UDP (syslog).
-> Two SEPARATE remoted processes, confirming the syslog listener is a
   real, distinct process from the pre-existing agent listener.

$ docker exec <container> cat /proc/net/udp

 3257: 00000000:0202 00000000:0000 07 ...
-> 0202 hex = 514 decimal, bound on 0.0.0.0 (all interfaces).
